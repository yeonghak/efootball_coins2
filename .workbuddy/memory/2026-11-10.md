## 11:03 修 draftDirty 误伤：补录持平不再被拦

### 问题
P1 第 7 项加的 `draftDirty` 防误写逻辑有副作用：
空白日 + 用户不动输入框 + 点保存 → toast「这天还没有记录，先输入金额」并拒绝写入。

但「昨天忘了补、金额没变化」这个场景下，**不动输入框正是正确操作**——
预填值就是上次余额，用户看到 3,180 与预期一致，不该逼他先改一下再改回来。

### 决策：把后果写在按钮上，而不是事后报错
否决的备选：
- 直接放行（删掉判定）：误触保存会凭空多一条持平记录
- 弹 showModal 二次确认：多一次点击，而用户点"保存"本身就是明确意图
- 输入框视觉区分「预填值/已输入」：要靠用户自觉，实现也更绕

采用：按钮文案随状态自适应，自解释且零额外点击
- 有记录 → `保存修改`
- 空白日 + 没动过输入框 → `记为持平 3,180`（直接点就写入，说明会发生什么）
- 空白日 + 改过金额 → `保存记录`

### 改动（pages/calendar/calendar.vue）
- 模板 `<button class="primary">` 文案 → `{{ saveLabel }}`
- 新增 computed `saveLabel`（放在 `deltaClass` 之后）
- `save()` 删除整段 `if (!selectedHasRecord && !draftDirty)` 拦截（4 行）
- `draftDirty` 保留，但语义从「拦截依据」变成「按钮文案依据」，注释同步更新

### 保留的校验（都在 save() 里，顺序不变）
清空金额 →「请输入当天账户总额」；负数 →「金币总额不能为负数」；未来日期 →「还不能记录未来日期」；
`upsertDayBalance` 返回 null → 「保存失败，请重试」

### 副作用（数据语义，非 bug）
补录一条**高于**后续日期的余额，会让后续那天的增量变负。
例：11-09 补 3180，而 11-10 已有 2750 → 11-10 显示 -430。
这是余额曲线的真实结果，dayIndex 按日期正序累计，不要试图"修正"。

### 验证
22 条断言通过：补录持平保存成功且金额 3180、记录数 1→2、
按钮三态切换（记为持平 3,180 / 保存记录 / 保存修改）、保存后立刻变「保存修改」、

### 测试经验
断言"清空输入框"必须在**真正空白**的日期上做，否则 `selectedHasRecord` 为 true，
按钮返回「保存修改」，测不到 dirty 分支。

## 12:35 P2 重构：getDayIndex 收口 + 公共样式提到 App.vue

### 一、getDayIndex 收进数据层
`dayIndex`（按日期正序累计出每天余额/变化/基线）原来在三处各写一遍：
- `calendar.vue` computed，返回 `{balance, change, baseline}`
- `stats.vue` computed，返回 `{balance, change}`（少了 baseline）
- `history.vue` load() 里内联算 `baselineOf[date]`

新增 `storage.js` `getDayIndex(data)`，返回 `{ [date]: {balance, change, baseline} }`：
- 内部 `records.slice()` 后排序，不改调用方数组
- 排序用 `date` 升序、同日用 `createdAt` 兜底（与 `normalizeRecords` 的去重规则一致）
- `previous` 初始为 `startingCoins`，无 records / data 为 null 时返回 `{}`

三处改为同一来源：
- calendar：`getDayIndex({ records: this.records, startingCoins: this.startingCoins })`
  （不传 `this.data`，因为 calendar 的 data() 里没有整份数据，构造轻量对象即可）
- stats：同样形式，与它已有的 `this.data` 并存
- history：`const index = getDayIndex(data)`，`delta = index[record.date].change`

### 二、公共样式提到 App.vue（非 scoped，编译进 app.wxss）
